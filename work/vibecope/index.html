Vibecope — AI coaching inside Claude Code

A macOS menu-bar app that watches how you prompt Claude Code and coaches you in real time — without ever making you wait.

LLM AgentsRAGAgent HooksSQLiteONNX EmbeddingsmacOS / SwiftRelease Engineering

The problem

Most people get mediocre results from coding agents for one reason: vague prompts. Existing tools evaluate prompts statelessly — they see one message with no memory of your project, your habits, or what you said three messages ago. The fix needed to live where the work happens, know your history, and never slow you down.

The architecture: hook = plumbing, server = brain

Vibecope splits into two deliberately unequal parts. A ~70-line UserPromptSubmit hook intercepts every prompt inside Claude Code and POSTs it to a local server. All intelligence lives in the server — one brain, not two:

User types prompt in Claude Code
        ↓
UserPromptSubmit hook (read stdin → POST localhost:7483)
        ↓
Server reads the session transcript for live conversation history
        ↓
RAG over SQLite (ONNX embeddings): project history + cross-project patterns
        ↓
Haiku call evaluates clarity against all three context layers
        ↓
Clear → silence. Vague → coaching injected as additionalContext,
so Claude sees the note alongside the prompt

Three layers of context

LayerSourceSolves
Current conversationSession transcript via the hookWhat was already said this session
Project historyRAG filtered by project pathComing back to Project A after a week on Project B
Cross-project patternsRAG across all projectsVocabulary habits — "text is too big" meaning "fix the line-height"

Each evaluated prompt is logged back to SQLite, and the next prompt updates the previous one's outcome — a behavioral feedback loop that lets the system learn whether its coaching actually worked.

The constraint that shaped everything: never make the user wait

  • The hook has a 500ms timeout — if the app is down, prompts pass through silently.
  • The server caps LLM evaluation at 2s — if it's slow, it returns green and analyzes asynchronously.
  • Coaching runs on Haiku regardless of the user's main model: one lightweight call per prompt, negligible cost.

Shipping it like a product, not a repo

Onboarding is download → open → done. The app installs its own hook files, edits settings.json, and starts the server — no git clone, no terminal, no API keys to paste. The build is signed with an Apple Developer ID and distributed as a notarized DMG.

What this demonstrates

  • Agent-native engineering — building on lifecycle hooks and context injection, the same primitives behind modern agentic systems.
  • Pragmatic RAG — local ONNX embeddings + SQLite instead of a vector-DB dependency, because the product needed zero-config install.
  • Latency-first design — graceful degradation at every layer; the user never pays for the feature's existence.
  • Full ownership — from hook protocol design to code signing and DMG distribution.
